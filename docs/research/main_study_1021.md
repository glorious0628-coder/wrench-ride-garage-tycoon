목적: 8시 첫 사람 시험과 10/26~28 공개 전에, 우리 게임 판단에 바로 쓰는 것만. 출처마다 "우리 게임에 쓰는 법" 한 줄.

## 1. 로블록스 공식: 첫 접속 경험(FTUE) — [Roblox Creator Docs: Onboarding](https://create.roblox.com/docs/production/game-design/onboarding)
- 첫 몇 분 = 하루 뒤 다시 오기(D1)를 가름. **단계마다 몇 명이 남는지(깔때기)**를 재고, 가장 많이 빠지는 단계부터 고침.
- **빨리 재미에 닿기**, 핵심 반복(무엇을·왜)을 가르치기, 낯선 조작은 화면에 보여 주기.
- 초반 레벨은 **빨리 오르게**(낮은 문턱). 시작 돈·아이템은 적당히(너무 많지도 적지도).
- 짧은·중간·긴 목표를 눈에 보이게. **온보딩 끝에 일부러 '기쁨의 순간'**(보상·연출).
- 우리 게임에 쓰는 법:
  - 튜토리얼 단계마다 **도착 시각 기록**(wr-dev '시험 기록' = 깔때기) → 8시 시험 뒤 어디서 막혔는지 숫자로.
  - 첫 차 3대 끝 = '기쁨의 순간'이 있는지 확인(정산 카드 + 레벨 업 + 정비소가 자란다 미리보기).
  - Lv1→2 문턱이 첫 10분 안에 넘는지 확인(economy.md).

## 2. 로블록스 공식: UI/UX — [Roblox Creator Docs: UI/UX design](https://create.roblox.com/docs/production/game-design/ui-ux-design)
- 작은 화면은 버튼·창·글자가 많으면 금방 질림 → **지금 상황에 맞는 버튼만**(상황 따라 바뀌는 조작).
- 중요한 것 먼저·찾기 쉽게, 색·크기·간격·움직임으로 눈길 — **움직임은 아껴서**.
- 버튼은 대비되는 판 안에(눌러 보이게), 눌림·뗌 상태, 소리·애니·진행 막대로 "됐다"를 알려 줌.
- 익숙한 약속: 오른쪽 위 X = 닫기, 회색 = 못 누름, 자물쇠 = 잠김. 색·아이콘·모양은 어디서나 같게(스타일 가이드).
- **탭 수·단계 줄이기**: 흐름도를 그려 군더더기 단계 찾기.
- 우리 게임에 쓰는 법: 사용자 "너무 복잡해보인다"와 같은 말 — 프롬프트 1개·윗줄 빼기(10-21 끝) 방향이 맞음. 다음 점검 = **튜토리얼 흐름도 탭 수 세기**(wr-ui), 잠긴 업그레이드는 자물쇠 + 회색으로 통일, 닫기 X는 늘 오른쪽 위.

## 3. 정비 게임 참고: Car Mechanic Simulator 평 (작업 모드에 직접 관련)
- 좋아하는 점: 진단 → 분해 → 고침 → 되살리기가 **차분한 반복**, 작은 성공이 계속 옴. ([GameGeeker review](https://gamegeeker.com/games/car-mechanic-simulator-2021/review?country=US))
- 싫어하는 점: **반복(볼트를 하나하나)**, 처음엔 어색함. 한 리뷰: 부품마다 볼트·클립을 하나씩 풀고, 새 부품 뒤에 뺀 걸 다 다시 끼워야 함 / **순서가 틀리면 막고 다음 것을 초록으로만 알려 줌 → "틀려 보고 배우는 선택이 있었으면"**. ([Xbox Tavern review](https://www.xboxtavern.com/car-mechanic-simulator-review-2))
- (리뷰 몇 개라 넓은 조사는 아님.)
- 우리 게임에 쓰는 법:
  - 볼트 수는 **부품당 적게**(지금 배터리·패드 2~4개 유지), 공구 업그레이드(임팩트 렌치)로 **반복이 줄어드는 느낌**이 '성장'이 되게.
  - 틀린 순서는 **막기만 하지 말고 웃긴 결과로**(배터리 단자 '파직'처럼) — 교과서 '틀려도 괜찮은'과 같음. 다음 부품 빛남은 튜토리얼에서만 강하게, 그 뒤엔 약하게.
  - 다시 끼우기 반복은 **묶어서 한 번에**(예: 같은 볼트 4개 = 꾹 한 번에 순서대로) 검토 — 시험 뒤.
