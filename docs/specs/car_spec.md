# 차 규격 (car_spec) — v0.9 (wr-design, 2026-10-20)

> 이 파일이 **차 크기·부품 이름·피벗·볼트 자리의 기준**이에요. wr-dev(코드), wr-art(분해도), wr-3d(메시), wr-builder(베이)가 모두 따라요.
> 바꾸고 싶으면 board.md에 "→ wr-design" 한 줄. 숫자는 **stud** 단위.
> 그림체 기준(기획서 8장 3번, 10-20 정정): **차체도 부품도 캐주얼한 생김새**(단순한 모양·또렷한 색). 다만 **실제 차 구성이 빠짐없이 제자리에** 있고 하나하나 알아볼 수 있어야 해요. 크기·자리 비율은 실제 차(가로배치 4기통 앞바퀴굴림 FF 중형 세단, 왼쪽 운전석) 기준.
> 언어·문화(사용자 10-20): **게임 글자 원문은 영어(미국식 단어: Hood, Trunk, Tire, Muffler, Windshield), 한국어는 번역.** 차는 서양권 아이들이 익숙한 미국 동네 세단 느낌.

| 항목 | 값 (stud) | 근거 |

| 차 1대 삼각형 | **목표 25k, 상한 35k** | §6 (캐주얼 부품이라 가볍게) |

**실제 차 대조 (v0.3, 내부 도안·정비 가이드로 확인)** — 근거 표는 §9.
- 크기: Camry XV70 4,880 × 1,840 × 1,445 mm, 휠베이스 2,820 mm / Sonata DN8 휠베이스 2,840 mm → 우리 기준(4.8 × 1.85 × 1.45 m, 2.8 m)과 맞아요. 타이어 215/55R17도 Camry 실제 사이즈.

**방향 약속 (모든 세션 공통)**
- 차 **앞 = −Z**, **위 = +Y**, 차의 **오른쪽 = +X**, 왼쪽(운전석 — 미국·한국 공통) = −X. → `CarModel:GetPivot().LookVector`가 차 앞을 가리켜요.
- **원점(모델 피벗)** = 앞뒤 바퀴 사이 한가운데의 **땅바닥** (0, 0, 0). 차를 리프트·바닥에 놓을 때 피벗 Y = 바닥 높이.
- 아래 모든 좌표는 이 원점 기준 **차 안 좌표(로컬)** 예요.
- Blender(wr-3d): 1 BU = 1 stud(Parcel Panic 파이프라인 단위 그대로), 위 = +Z. **Roblox에 들어갔을 때 앞이 −Z**가 되게 내보내요(Parcel Panic `pbr_glb`의 "Roblox −Z 앞이 되게 180° 돌리기" 규칙과 같은 얘기). 들여온 뒤 `tools/3d_check`로 앞 방향 확인.
- 왼쪽·오른쪽 짝 부품(바퀴 등)은 **한 메시를 180° 돌려서** 써요. 음수 크기(거울 뒤집기) X — MeshPart는 거울 크기가 안 돼요.

## 1. 크기 정한 이유 (R15 · 다른 차 게임)

- **R15**: 서 있는 키 약 5.0~5.3 stud, 팔 포함 어깨 폭 약 4 stud, 앉으면 엉덩이 → 머리 끝 약 3.0 stud. 키 기준으로 재면 1 stud ≈ 0.34 m라서, **0.28 m 환산 차는 사람에 비해 약 1.2배 커 보여요** → 아바타가 끼이지 않고, 기획서의 '전폭 1.15배·층고 확보'와 같은 방향.
- 앉은 머리: 좌석면 Y 1.5 + 앉은 R15 약 3.0~3.5 = **4.5~5.0**, 지붕 안쪽 5.5 → 머리 위 0.5 이상 여유. (앉은 키는 공개 자료가 없어 추정 — **wr-dev가 Studio에서 Seat에 R15 앉혀 `GetBoundingBox` 실측 부탁**, 5.3을 넘으면 지붕을 올려요.)
- 폭 7.6이면 앉은 R15 두 명(각 4 폭)은 어깨가 0.4쯤 겹쳐요 — 로블록스 차 대부분이 그래요. 손님 NPC는 운전석에 1명만 앉으니 문제 없어요.
- **인기 로블록스 차 게임 크기**: API 조사(`notes/research/api/2026-10-20_roblox_car_scale.md`) 결과, 0.28 m/stud는 Studio 월드 설정·개발자 포럼이 쓰는 값으로 확인했어요. Greenville·Car Dealership Tycoon·Driving Empire·Jailbreak 등 **게임별 차 크기는 공개 수치가 없어서** 짐작으로 채우지 않았어요.
- 그래서 기준 = 0.28 m/stud 실제 비율 + 폭 1.15배. 실제 비율 세단이 17 stud쯤이라, '차가 사람보다 조금 큰' 로블록스 현실풍 차 게임 느낌과 맞아요.
- 나중에 확인할 것: 프로토타입에서 17 stud 차와 R15를 나란히 놓고 메인·사용자가 보기에 너무 크면 **전체 0.9배(15.3 stud)** 까지 줄일 수 있게 숫자를 비율로 관리(코드는 `CarScale` 하나로).

## 3. 부품 두 층

| 층 | 뜻 | 메시 | 충돌·조회 |
|---|---|---|---|
| ① **고치는 부품** | 떼고 끼우는 것. `Condition`·볼트가 있음 | 부품마다 따로 MeshPart | 붙어 있을 땐 CanCollide 끔, CanQuery 켬(클릭) |
| ② **보이는 부품 (장식)** | 고치진 않지만 보닛 열고·리프트 올리면 보여야 하는 진짜 부품 | 몇 덩어리로 묶은 MeshPart | CanCollide·CanQuery·CanTouch 끔 |
| (고정 몸체) | 차 뼈대·겉껍데기 | Chassis, Shell, Glass | Chassis만 충돌(단순 Box) |
| (움직이는 장식) | 고치진 않지만 작업 중 움직임 | 예: 브레이크 캘리퍼(젖혀짐) | ②와 같음 |

### 3-1. 모델 구조 (이름은 코드에서 그대로 씀)

```
CarModel (Model, PrimaryPart = Chassis, 피벗 = 원점)
├─ Chassis            (MeshPart, 고정: 바닥판·뼈대·간단한 실내) ← 모든 Snap_/LiftPoint_/Fluid_ 어태치먼트가 여기
├─ Body (Folder)
│   ├─ Shell          (고정: 지붕·기둥·펜더·문(프로토타입은 닫힌 채 Shell에 포함))
│   ├─ Glass          (고정: 창 전부, 반투명)
│   ├─ Hood           ① 
│   ├─ Bumper_F       ①
│   └─ Bumper_R       ①
├─ MechanicalParts (Folder)
│   ├─ Battery        ①
│   ├─ Wheel_FL / Wheel_FR / Wheel_RL / Wheel_RR   ① (Model: Rim[PrimaryPart] + Tire)
│   └─ BrakePads_FL / _FR / _RL / _RR               ① (패드 2장 한 세트 = 한 메시)
├─ Moving (Folder)
│   └─ BrakeCaliper_FL / _FR / _RL / _RR           (움직이는 장식: 패드 뺄 때 위로 젖혀짐)
└─ Decor (Folder)      ② 장식 덩어리 (§5)
```
- 볼트·너트 메시는 3D에 넣지 않아요. **코드가 `Bolt_n` 어태치먼트 자리에 공용 볼트 메시를 붙여요**(LugNut / Bolt_M10 / TerminalNut 3종). 3D는 볼트 자리에 구멍·자리만.
- 프로토타입: **고치는 부품 12개**(Hood, Bumper_F, Bumper_R, Battery, Wheel×4, BrakePads×4) + 고정 3(Chassis, Shell, Glass) + 캘리퍼 4 + 장식 덩어리. (원래 기획 '12개 부품' = 고치는 부품 12개로 읽었어요.)

### 3-2. 어태치먼트·속성 약속 (제안 — 코드 주인은 wr-dev, 바꾸면 알려 주세요)

**부품(①)에 붙는 것**
| 이름 | 뜻 |
|---|---|
| `SnapAttachment` | 부품의 피벗 자리. 축 = 차 축(설치됐을 때 Rotation 0). `PivotOffset`도 여기에 맞춤 |
| `Bolt_1` … `Bolt_N` | 볼트 머리 자리. **어태치먼트 +X 축(Axis) = 볼트가 빠져나오는 방향** |
| `Grip_L`, `Grip_R` | 두 손으로 들 때 손 자리(한 손 부품은 `Grip_R`만) |
| `Hinge` | 열리는 부품의 경첩 축(Hood, 캘리퍼). +X 축 = 도는 축 |

**Chassis에 붙는 것**
| 이름 | 뜻 |
|---|---|
| `Snap_<Slot>` | 그 부품이 끼워질 자리 (예: `Snap_Battery`, `Snap_Wheel_FL`) — 부품의 `SnapAttachment`와 맞으면 끝 |
| `LiftPoint_FL/FR/RL/RR` | 리프트 팔이 닿는 자리(문턱 아래) |
| `Seat_Driver`, `Seat_Passenger` | 앉는 자리 |
| `Exit_L`, `Exit_R` | 손님 내리는 자리(차 밖 1.5) |
| `FX_HoodGap`, `FX_Leak_Engine`, `FX_Exhaust` | 고장 연출(연기·누유·배기) |
| `Fluid_OilFill`, `Fluid_OilDrain`, `Fluid_Coolant`, `Fluid_BrakeFluid`, `Fluid_Washer` | 액체 넣고 빼는 자리(엔진오일 보충은 Lv1 일, 메시는 장식에 있음) |

**부품 속성(Attribute)**
| 속성 | 예 | 뜻 |
|---|---|---|
| `PartKind` | "Battery", "Wheel", "BrakePads" | 종류(상점·도감용) |
| `Slot` | "Wheel_FL" | 자리 |
| `Condition` | 0~100 | 기획서 6장 그대로 |
| `BoltCount` / `BoltsRemaining` | 4 / 4 | |
| `Requires` | "Wheel_FL" / "Hood:Open" / "Lift:Wheel" | 먼저 해야 할 것(쉼표로 여러 개) |
| `CarryMode` | "OneHand" / "TwoHand" / "Roll" / "Crane" | 운반 방식 |
| `MassKg` | 16 | 손맛·표시용 |
| `Tool` | "Hand" / "Wrench" / "Lug" / "Clip" / "Cutter" / "Crane" | 필요한 공구 종류(임팩트 렌치는 Wrench·Lug의 업그레이드) |

**운반 방식**: OneHand = 보통 걸음 · TwoHand = 걸음 70%, 그동안 공구 못 씀(기획서 '두 손 운반 모션') · Roll = 바퀴 굴리기, 걸음 85% · Crane = 엔진 크레인으로만.

### 3-3. 리프트 높이 (차 피벗을 올리는 양)

## 5. ② 보이는 부품 (장식) — 빠짐없이, 하지만 캐주얼하게

- 모양은 단순하게(호스 = 6각 단면 튜브, 배선 = 몇 가닥 묶음 1줄, 볼트 머리는 장식에선 생략 가능). 대신 **있어야 할 게 다 있고, 제자리에, 진짜로 이어져** 있어야 해요 — 보닛을 열면 "아 이게 엔진, 이게 배터리, 이게 라디에이터" 하고 알아보게.

기준 차: **가로배치 직렬 4기통, 앞바퀴굴림(FF), 왼쪽 운전석, 앞 맥퍼슨 스트럿 / 뒤 토션빔 또는 멀티링크**. 진짜 자리·진짜 연결(호스는 진짜로 이어진 곳끼리, 배선은 커넥터까지).
