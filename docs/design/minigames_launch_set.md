# 공개 판 미니 게임 6개 — 새 4개 설계 (v0.4 초안)

> **⚠ 최신 = `notes/gpt/main/minigames_launch_decision.md`(GPT 2라운드 결론 10개 — 순서·공짜 토크 렌치·토크 판정·자동 완료 1칸·겹침·화면 위/아래 가운데·팁).** 그 파일이 아래 칸과 본문보다 우선.

> 2. **냉각수 공기 빼기**: 따로 미니 게임 X. 채운 뒤 일반 조작 한 번 **"Start engine"**(지금 수리 확인 시동 연출 재사용)을 '공기 빼기 겸 확인'으로. A25A의 3,000 rpm·스캐너 절차는 게임에서 단순화 — 화면 글로 사실이라고 주장하지 않기.
> 3. **토크 딸깍**: 현실대로 **차를 내린 뒤(바퀴가 바닥에 닿은 뒤)에만** 프롬프트. 지금 바퀴 일 흐름에 '내리기'가 있는지 wr-mini가 코드 확인 → 없으면 순서 맞추기. 토크 렌치 = 상점 공구($300, 첫 묶음 공구). 3D가 늦으면 본문 대안(2D + 빈 손). `tools_real.md` 딸깍 절차는 wr-mini가 직접 확인.
> 4. **차종별 값**(문 라벨 psi·냉각수 색): 근거 있는 값만 차 데이터에. Camry 기준 세단 = 35 psi·분홍. SUV·해치백은 wr-mini가 `claude_api.py research`로 찾아 근거 링크와 함께 넣기 — 못 찾으면 board에 '→ wr-carbook'.

> 6. **위험 3 대응**: 10/25(D3) 저녁 wr-mini가 6개 진행을 board에 보고 → 메인이 품질 판단 → 빠질 게 있으면 **사용자에게 '빼기 vs 공개 미루기'를 미리 물음**(메인).

> 8. **'뾰로롱'**: Perfect 순간 3D 반짝임 = wr-vfx `Sparkle_Perfect`, 화면 안 글자 연출 = wr-ui.
> 9. **다른 게임에서 가져올 장치 8개**(사용자 "기존 미니 게임 분석해서 재창조해도 좋아, 재밌고 익히기 빠르면" · 근거 `notes/research/minigame_refs_1022_b.md`, 링크 확인된 것만) — **전부 적용**:

## ⓒ 흠집 광내기 (Scratch Polish) — `BODY_SCRATCH_LIGHT`

| 항목 | 내용 |
|---|---|
| **1. 현실 절차** | **손톱 테스트**로 깊이를 봐요. 손톱이 안 걸리면 클리어 층 안의 얕은 긁힘이라 **광내기(폴리싱)로 줄이고 칠은 필요 없어요**. 살짝 걸리면 전문 광 작업, 깊게 걸리면 다시 칠해요 (`11_body_paint` 흔한 칠 고장 표 [27]). |
| → 미니 게임이 맡는 부분 | **광내기 문지르기 하나.** 손톱 테스트는 미니 게임이 아니라 짧은 일반 조작(판단)이에요. 있으면 앞에, 없으면 확인 필요. |
| **2. 시작 · 이어짐** | 시작: `BODY_SCRATCH_LIGHT` 차 → (손톱 테스트) → 폴리셔 도구를 들고 흠집에 프롬프트 **"Polish"**.<br>끝: 흠집 데칼이 사라지고 반짝 → 그 고장 해결 → 일 계속. |
| **3. 틀 값** | **틀 ③ 문지르기** · 시간 [게임] 4~6초 (서버 최소 2.5초)<br>성공: 흠집 칸을 모두 지움<br>Perfect: 6초 안에 모두 지움<br>실패: 없음(시간이 걸려도 Good)<br>도움: 3번 '늦게 끝' → 칸당 필요 문지름 −1 (Perfect 불가)<br>Perfect 팁: **$10** (한 일에 한 번)<br>Auto: Good, 진행 막대 4~5초 |
| **4. 서버 판정** | 서버가 정함: 흠집 칸 배치(예 6×4 중 흠집 칸), 칸당 필요 문지름 수, 시작 시각.<br>클라가 보냄: `(sessionId, 순번, 지나간 칸 번호 묶음)`.<br>막을 핵: 한 번에 모든 칸 보내기 → **초당 칸 수 상한 + 이웃 칸만 이어지기** 검사 / 2.5초 안에 끝내기 → 최소 시간 / 다른 차·먼 거리에서 시작 → `Guard`(거리·고장 있음·도구 들고 있음) / 완료 두 번 → 단 한 번 처리. |
| **5. 화면** | 단자 닦기 ③ 화면 그대로 쓰고 그림만 바꿔요: 얼룩 → **차 칠 위 흰 긁힘 줄**, 솔 → **폴리셔 패드**, 다 지우면 반짝. |
| **6. 필요한 것** | 소품: 폴리셔(손 도구), 흠집 데칼 · 소리: 폴리셔 윙, 반짝 · 글: 아래 표.<br>**대체안**: 폴리셔 3D가 늦으면 화면 안의 2D 패드 그림만 쓰고 손엔 아무것도 들지 않아요. 샌딩기·스프레이건처럼 다른 도구로 대신하면 '칠 필요 없음'이라는 현실과 어긋나므로 쓰지 않아요. |
| **7. 겹칠 때** | 아래 '겹침 규칙' 표를 따라요. 차체 마무리 손동작이라 우선순위가 낮아요. |

## ⓓ 냉각수 채우기 (Coolant Fill) — `RAD_LEAK` 라디에이터 교체 뒤

| 항목 | 내용 |
|---|---|
| **1. 현실 절차** | 냉각수를 빼고 → 교체 → 채우고 → 공기를 빼요 (`04_cooling` ⑤ [3][6]).<br>보조탱크에는 **F·L 줄**이 있고, **엔진이 차가울 때** F~L이면 정상, L 이하면 **F까지** 보충해요 [7].<br>**물만 넣지 말 것** [6]. Camry는 **분홍 SLLC**, 미국판은 50:50으로 미리 섞여 있어요 [7][19].<br>**뜨거울 때 캡을 열지 말 것** [14]. |
| → 미니 게임이 맡는 부분 | **보조탱크에 F 줄까지 붓기(누르고 있다 떼기) 하나.**<br>실제 라디에이터 쪽 주입 절차와 용량은 노트에 "(확인 못 함)"이라 **탱크 F/L 줄로 단순화**해요. |
| **2. 시작 · 이어짐** | 시작: 새 라디에이터 장착 완료 → 냉각수 통을 들고 보조탱크에 프롬프트 **"Fill Coolant"**.<br>끝: 공기 빼기 단계 → 일 완료. 공기 빼기는 **확인 필요**: A25A는 "캡 열고 기다리기"로는 부족하고 3,000 rpm 사이클 + 스캐너로 채우기 모드에 들어가요 [16]. 게임에서 짧은 일반 조작 1개로 할지, 생략할지 결정이 필요해요. |
| **3. 틀 값** | **틀 ② 선 맞춰 채우기** · 시간 [게임] 3~5초<br>성공 띠: L~F<br>Perfect: F 바로 아래 좁은 띠 [게임]<br>L 아래에서 떼면: "Not enough" → 이어서 더 붓기(벌 X)<br>F 위로 넘기면: "Too full" → '빼기' 탭 한 번(벌 X, Perfect 불가)<br>도움: 3번 놓치면 띠 +20 % (Perfect 불가)<br>Perfect 팁: **$10**<br>Auto: Good, 4~5초 |
| **4. 서버 판정** | 서버가 정함: 채우는 속도 곡선, 시작 높이, 띠·Perfect 띠 위치.<br>클라가 보냄: `누름`·`뗌`·`빼기` 의도만. 높이는 **서버가 받은 시각의 차**로 계산해요.<br>막을 핵: 높이·결과 값 보내기 → 받지 않음 / 라디에이터가 없는데 시작 → `Guard`(그 차 고장 단계 = 라디에이터 장착 완료, 통 들고 있음, 거리) / 누름 없이 뗌·중복 → 순번으로 버림. |
| **5. 화면** | 틀 ② 화면에서 그림만 바꿔요: 눈금 막대 → **반투명 탱크 옆면 + F·L 줄**, 액체 색 = 분홍. 큰 버튼 "Hold to pour". |
| **6. 필요한 것** | 소품: 냉각수 통(분홍) · 3D: 보조탱크는 엔진룸 오른쪽 앞(조수석) [2]에 있고, 이미 있는지 **확인 필요** · 소리: 꿀렁꿀렁 붓기 · 글: 아래 표.<br>**색 확인 필요**: 게임 차가 Camry 기준이 아니면 브랜드 색(Honda 파랑 [20] 등)이 달라요. fault_catalog의 "green"은 Camry와 맞지 않아요.<br>**대체안**: 탱크 3D가 늦으면 화면 2D 탱크 그림만 쓰고, 3D는 지금 있는 엔진룸 위치에 프롬프트만 둬요. |
| **7. 겹칠 때** | 아래 표. 고장을 고치는 일의 마무리라 우선순위는 중간이에요. |

## ⓔ 타이어 공기압 (Tire Fill) — 새 타이어 끼운 뒤

| 항목 | 내용 |
|---|---|
| **1. 현실 절차** | 권장 공기압은 **운전석 문 라벨** 값이에요(옆면 숫자는 '최대'). Toyota는 **식은 상태**에서 재요 (`03_wheels_tires` ④ [11][13]). Camry 2018은 **앞뒤 35 psi** [11]. |
| → 미니 게임이 맡는 부분 | **라벨 숫자까지 공기 넣기(누르고 있다 떼기) 하나.** 라벨 숫자는 화면에 스티커로 보여 줘요(작은 읽기). |
| **2. 시작 · 이어짐** | 시작: 새 타이어를 휠에 끼운 뒤 → 공기 호스에 프롬프트 **"Inflate"**. 어떤 고장 키에서 새 타이어를 끼우는지는 **코드에서 확인 필요**.<br>끝: 바퀴를 차에 다는 단계 → (ⓕ 토크) → 일 계속. |
| **3. 틀 값** | **틀 ②** · 시간 [게임] 3초<br>성공 띠: 라벨 값 ± [게임] 값<br>Perfect: 라벨 값 정확히(좁은 띠)<br>넘으면: '빼기' 탭(벌 X)<br>모자라면: 다시 누르기<br>도움: 3번 놓치면 띠 +20 % (Perfect 불가)<br>Perfect 팁: **$10**<br>Auto: Good, 4~5초 |
| **4. 서버 판정** | 서버가 정함: 그 차의 라벨 값(차 데이터), 시작 압력, 오르는 속도, 띠.<br>클라가 보냄: `누름`·`뗌`·`빼기`만.<br>막을 핵: psi 값 보내기 → 안 받음 / 타이어가 안 끼워졌는데 시작 → `Guard` / 빼기 연타로 팁 되풀이 → Perfect 팁은 일당 1번. |
| **5. 화면** | 틀 ② 화면에서 그림만 바꿔요: 눈금 → **둥근 공기압 게이지 바늘**, 위쪽에 **문 라벨 스티커 "35 PSI"**. 버튼 "Hold to fill", 작은 '빼기' 버튼. |
| **6. 필요한 것** | 소품: 공기 호스(벽 릴), 라벨 스티커 그림 · 소리: 쉬익 넣기·빼기 · 글: 아래 표.<br>**확인 필요**: Camry가 아닌 게임 차의 라벨 값 → 노트에 없어요. 차 데이터에 넣기 전에 wr-carbook 확인이 필요해요.<br>**대체안**: 호스 3D가 늦으면 지금 있는 타이어 탈착기 옆에서 프롬프트만, 화면 2D 게이지로 진행해요. |
| **7. 겹칠 때** | 아래 표. 바퀴 일에서 가장 먼저 Good으로 넘기는 후보예요. |

## ⓕ 토크 딸깍 (Torque Click) — 바퀴 일 마지막

| 항목 | 내용 |
|---|---|
| **1. 현실 절차** | 접촉면 청소 → **너트를 손으로 고르게** → **차를 내림(바닥에 살짝 닿게)** → **별(대각선) 순서로 2~3번 돌며 토크 렌치**로 Camry 103 N·m(76 ft-lbf). **임팩트 렌치 금지**, 토크 스틱도 마지막엔 토크 렌치 (`03_wheels_tires` 휠 ④ [12][32][33]).<br>"딸깍에서 더 힘주지 않음"은 minigames.md의 Park Tool 인용 → **`tools_real.md`로 확인 필요**. |

## 겹침 규칙 (한 차 ≤ 2번, 합 ≤ 20초)

서버가 차마다 `mgCount`를 세요. **3번째부터는 Auto처럼 'Good'**(진행 막대, Perfect 팁 없음)으로 처리해요. 우선순위가 높은 것부터 직접 하게 해요.

| 순위 | 미니 게임 | 이유 |
|---|---|---|
| 1 | 휠 밸런스 (6~8초) | 고장의 핵심 손동작, 직접 산 장비 |
| 2 | 단자 닦기 · 냉각수 채우기 | 그 고장을 고치는 손동작 |
| 3 | 토크 딸깍 (첫 바퀴만) | 마무리, 렌치를 산 보람 |
| 4 | 흠집 광내기 | 차체 마무리 |
| 5 | 타이어 공기압 | 가장 짧고 반복이 많음 → 먼저 넘김 |

- **여러 바퀴**: 토크·공기압은 **그 일의 첫 바퀴만** 미니 게임이에요. 나머지 바퀴는 바로 Good으로 처리하고 `mgCount`에 세지 않아요.
- **같은 틀이 연속**(예: 공기압 ② → 냉각수 ②)이면 뒤의 것을 Good으로 넘겨요(§2).
- **첫 만남**(`mgPlays[kind] = 0`)은 순위보다 먼저 직접 하게 해요. 단, 그래도 한 차 2번 상한은 지켜요.

### 공개 전에 못 되면 빼는 기준 (하나라도 걸리면 그 미니 게임은 안 넣음)

1. 결과를 클라가 정하는 길이 남아 있음(서버 판정 미완).
2. 300 ms 지연에서 '화면을 보고 제대로 누른' 입력이 실패로 나오는 일이 잦음(기준 % 는 팀이 D5 전에 정할 것).
3. 일을 막는 경로가 있음(실패·버그로 일이 안 끝남).
4. 현실 절차와 어긋나는 그림·도구(예: 토크를 임팩트 렌치로, 흠집을 칠로).
5. 겹침 규칙(한 차 ≤ 2, ≤ 20초)이 깨짐.

뺀 것은 **지금 있는 손맛(꾹 누르기)으로 일이 끝나게** 둬요. 단자 닦기는 지금 꾹 1.5초 그대로예요.

## 토크 렌치 3D가 늦을 때의 대안 (1개)

**"2D 렌치 + 빈 손"**으로 가요.
- 상점과 미니 게임 화면에는 **클릭형 토크 렌치 2D 그림**을 써요.
- 미니 게임 중 캐릭터 손에는 **아무 렌치도 쥐어 주지 않아요.**

임팩트 렌치나 일반 라쳇 모델로 대신하면 '마지막은 토크 렌치, 임팩트 금지'(03 [32][33])를 어기므로 쓰지 않아요. 판정·딸깍 소리·진동은 3D와 무관해서 그대로 돼요.

## 놓쳤을 수 있는 위험 3개

1. **토크 '0.6초 안에 떼기'와 폰 핑**: 딸깍은 서버 시각에 나는데, 클라 화면은 그보다 늦게 보여요. 300 ms 아이는 제대로 떼도 "Over-tightened"가 날 수 있어요.
   → 클라가 딸깍을 **예정 시각에 미리 보여 주고**, 서버 구간에 지연 여유를 둬요(값은 D5 시험으로). 클라 시각을 믿는 쪽으로 돌아가지는 않아요.
2. **현실은 '차를 내린 뒤' 토크**(바퀴가 바닥에 닿아야 안 돎, 03 [32]): 지금 게임 흐름이 리프트 위에서 조이게 되어 있으면 현실과 어긋나요.
   → 바퀴 일 마지막에 '차 내리기' 단계가 있는지 코드 확인이 필요해요. 없으면 토크 프롬프트를 내린 뒤에만 띄워요.
3. **빼는 기준과 사용자 결정이 충돌**: 사용자는 "31일 전에 다 있어야, 나중에 갑자기 추가는 이상하다"고 했어요. 품질 미달로 하나를 빼면 결국 공개 뒤에 추가하게 돼요.
   → **D3 저녁에 진행을 보고 "빼기 vs 공개 미루기 vs 나중 추가"를 사용자에게 미리 물어야 해요.**

(이 밖의 확인 필요 항목: 새 타이어·바퀴 교환 뒤 TPMS 초기화(03 [13]), 냉각수 공기 빼기 단계, Camry가 아닌 차의 라벨 공기압·냉각수 색, `tools_real.md` 딸깍 절차.)
