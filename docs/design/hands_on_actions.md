## 0. 한 줄 결정
1. **'몸으로 직접' 원칙 4개**: ① **가까이 가야 함**(걷기 — 22 stud 밖에서 버튼 X) ② **몸이 움직임**(문 열기·앉기·키 돌리기 등 애니) ③ **효과는 손이 닿는 프레임에 일어남**(애니가 끝나기 전에 결과 X) ④ **반복되면 짧은 판**(같은 차 두 번째부터는 문이 열린 채 앉아 있음 — 처음 6초 → 3초).
2. 시동 걸기 = **걸어서 운전석 문 → 'Get in'(프롬프트 하나가 문 열기·앉기를 이음) → 앉으면 카메라가 계기판으로 → 큰 버튼 하나 'Start'(두 차 모두 탭 한 번) → 브레이크 밟기·'Press START'·점검등·크랭크가 이어짐 → 결과 단서 → 엔진 끄고 내리기.** 폰 조작 = 프롬프트 1개 + 큰 버튼 1개 + 모퉁이 Exit. 전체 **약 3.5~5.5초**(carbook 템포). **같은 차를 시험하는 동안은 앉은 채**(보닛 레버도 앉아서).
3. **계기판 경고등이 진짜 단서가 됨 — 단 거짓 진단을 가르치지 않게**(GPT r1 최대 위험): 시동 전 ON에서 **점검등이 켜지고, 일부는 몇 초 뒤, 대부분은 시동 뒤에 꺼짐**('모두 켜졌다 모두 꺼짐'은 틀림 — 차종마다 다르고 정상 차도 충전등은 시동 전 ON에 켜짐). **약속은 둘뿐**(GPT r2): 시동 전 켜진 모습 = 점검, **시동 뒤에도 남는 등 = 단서**(설명서가 뒷받침하지 않는 '몇 초 뒤 어떤 등이 꺼진다' 규칙은 안 만듦). 시동 자체가 실패하면 '시동 뒤 남음' 판정은 못 하므로 **딸깍 소리와 계기판 밝기**를 보여 주고, 경고등 하나로 배터리 고장을 확정하지 않음. 증상 연출은 **고장마다 따로**(죽은 배터리: 어둡거나 안 켜짐 + 침묵/빠른 딸깍 · 약한 배터리: 흐림 + 느린 크랭크 …). **폰에선 가장 중요한 경고등 하나를 화면에 크게**(아이콘 + 짧은 말 + 소리). 시동 안 걸릴 때 소리 4종(침묵 / 빠른 딸깍 / 큰 딸깍 한 번 / 크랭크만)은 지금 단서(`Diagnosis.startClue`)와 같음.
4. **공개 전(10/31)에는 안 넣음**(문·좌석·계기판 3D, 애니, 서버 상태가 전부 새것이라 품질 못 맞춤 + 지금 버튼 방식도 반응이 풍부: 엔진 소리·헤드라이트·Rosa 반응). **공개 뒤 11/7 차체(문) → 11/14는 '시동 한 흐름'만**(한 차종 · **튜토리얼 첫 차의 배터리 시동 사례**부터 — 폰 화면·손 확대 검사 뒤 넓힘). 버튼 방식은 **끝까지 보험**으로 남김.
5. 나머지 행동도 같은 원칙으로 줄마다 표(§3) — 우선순위 = 일마다 가장 자주 하는 것부터.

## 2. 시동 걸기 흐름 (단계표) — carbook `notes/research/mechanic_motions_1022.md` ⑫ 반영
> 현실(캠리 XV70 사용설명서, carbook이 열어 읽음): **스마트 키 차** — 주차 브레이크·**P 확인 → 브레이크 페달을 확실히 밟음 → 계기판에 시동 안내 메시지('Press START') → 엔진 스위치를 짧고 확실히 한 번(꾹 누를 필요 없음) → 시동이 걸릴 때까지 또는 최대 30초 크랭크 → 시동이 완전히 걸릴 때까지 브레이크 유지.** 키 꽂는 옛 차 = 키를 ON → START(스프링으로 돌아옴). (carbook: 3인칭 영상을 못 찾아 앉는 몸 자세는 확인 못 함 — 애니는 말·장면 몇 개 + R15 단순화.)

- **시간 (carbook 표 맞춤)**: 전체 **약 3.5초(선택 단계 뺀 것) ~ 5.5초(보호용품 포함)**. 같은 차 두 번째부터는 앉아 있어 **약 2초**(5~8단계만). 한 일에 2~3번 시험.
- **시동이 안 걸릴 때의 소리 4종 + 계기판**(carbook ⓓ — 영상 [11] + 설명서): ① **침묵 + 계기판에 불이 하나도 안 켜짐 = 배터리 전압 0에 가까움**(희미하게 켜지면 약한 배터리) ② **빠른 딸깍딸깍 + 흐린 등 = 배터리 약함·케이블** ③ **큰 딸깍 한 번 = 시동 모터(솔레노이드)** ④ **크랭크는 되는데 안 걸림 = 연료·불꽃·공기**(휘발유 냄새 = 침수). → 지금 단서(`clue.start.*`)와 같은 4종을 소리 + **계기판 모습**으로.
- **브레이크 시험**도 같은 흐름: 앉은 채로 '페달' 버튼(길게) → 끼익/드르륵이 휠 쪽에서 나고 카메라가 그 바퀴로 잠깐 이동(지금 `Diagnosis.brakeClue`). 걷지 않고 앉아서 두 시험을 이어 함. **(두 사람 피 빼기는 따로 — minigames ④)**.
- **키 차 vs 버튼 차**: 현실 둘 다 있음. **`ignition = "button" | "key"`는 차(트림/시대)별 속성**. 기본 세단·SUV 등 요즘 차 = 버튼(캠리 XV70 = 스마트 키), **튜토리얼 Rosa의 차는 기본 트림이라 키**("When I turn the key…" 그대로), **시대 차(era_cars) = 키**. **입력은 두 차 모두 'Start' 탭 한 번**(GPT r2) — 차이는 **캐릭터 손동작·소리·글**(버튼 차 = 브레이크 밟고 'Press START' 뒤 손가락, 키 차 = 손목으로 ON→START, 놓으면 스프링으로 돌아오는 움직임 연출).
- **친구/직원과 같이**(공개 뒤): 한 명이 운전석, 다른 한 명은 **엔진룸에서 듣기·보기**(청진기로 시동 모터 소리 구분 — 있는 도구, 벨트가 도는지). 직원 'Call'(staff §5)이 오면 **직원이 시동을 걸고 나는 엔진룸에서 들음**. 피 빼기와 같은 '두 사람 순서' 틀.
- **못 끝냈을 때 되돌리기**: ① 기능 스위치 `Config.Features.HandsOn` 꺼짐 = 지금 버튼 방식 ② 그 차종에 문/좌석/계기판 3D가 없으면 저절로 버튼 방식(`LiveLumps`와 같은 확인) ③ 흐름이 20초 막히면 카드에 작은 **"Try from here"** 버튼 ④ 죽거나 나가면 세션 종료.
- **서버 판정**(§4): **서버 상태기계가 주인**(차별 점유자 + `Seated → ON → Cranking → Result → Exit`)이고 `Seat`는 연출·착석 확인용(GPT r1: Seat만 믿으면 3초 재착석 제한·점프 하차로 재시험·자동 하차가 흔들림 — anchored Seat 자체는 문제 아님). 매 입력에서 **같은 플레이어 · 같은 차 · 살아 있는 캐릭터 · 현재 단계 · 요청 간격** 확인, 진입은 서버가 문 앞 거리와 빈자리를 보고 승인(클라가 "앉았다"를 말해도 안 믿음). 지금 `TryCar`의 22 stud 규칙을 이걸로 대체. 카메라 판정은 서버에 안 넣음(클라 전용).
- **시동 막는 조건**(실제 안전 규칙, GPT r2): **작업 화면(`WorkEnter`)만으론 부족** — 화면을 닫고도 엔진룸 앞에서 손으로 작업 중일 수 있으니 서버는 그 차의 **작업 중 상태 + 위험한 작업 자리**를 함께 봄. 손을 대는 작업은 금지("Someone is working on it"), **표시된 안전한 '듣기 자리'에서 관찰하는 건 허용**(협동 듣기). 넓은 거리 하나로 판정하지 않고 **행동과 자리**로 구분. 차가 잭/리프트 위에 떠 있거나 배터리가 빠져 있으면 반응 없음.
- **서비스 알림**: 오일을 갈았다고 **오일 압력 경고등이 꺼지는 보상은 만들지 않음**(압력 경고등과 교환 알림은 다른 것 — GPT r1 잘못된 학습). 정비 알림 재설정(Camry는 계기판 메뉴)은 나중 후보 ⓒ carbook.
- **앉은 채 유지 + 보닛**(GPT r2): 같은 차를 시험하는 동안은 **앉은 채로** 시동·브레이크·작업 카드 확인. **보닛 레버는 앉아서 실내 'Hood' 동작으로**, 그다음 **시동을 끄고 내린 뒤** 앞쪽 걸쇠를 풀고 들어 올림(밖에서 문을 다시 열어 손만 넣는 경로는 기본으로 안 만듦).
- **하지 말 것**(carbook): 버튼 한 번에 시동되는 '가만 서 있는 캐릭터' · 캠리를 키 돌리는 차로 그리기 · 시동 소리를 전부 '부릉'으로 · 보호용품을 모든 손님에게 강제.
