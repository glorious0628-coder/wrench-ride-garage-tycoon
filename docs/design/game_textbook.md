## 한 줄 요약 (원본 그대로)
**재미는 플레이어의 기대를 디자인이 정확히 만들고, 그 기대를 배신하지 않을 때 생긴다.** 하나의 느낌(일관성), 서툴러도 뜻을 알아듣기(보정), 세상이 내 행동에 반응(디테일), 할 일이 많아도 목표는 하나(전환 비용).

## 우리의 '하나의 느낌'과 '하나의 목표' (제안 — 사용자 결정)
- **하나의 느낌**: "동네 정비소 주인이 되어, 고장 난 차를 '아하!' 하고 알아내 손으로 고치고 손님을 웃게 하는 따뜻한 정비 — 틀려도 괜찮아."
- **공통 진행 목표**: "**내 정비소가 동네 최고 정비소로 자라는 것**(간판·베이·장비·건물이 눈에 보이게 커짐)." — v0.2 GPT 반박 받아들임: 이걸 '모든 재미를 하나로 묶는 목표'라고 하면 억지. 기획서는 처음부터 **두 축(손님 정비 / 복원·매매)**이고, 시대 차는 '팔아 돈 벌기'가 아니라 '발견해 남기기'. → 정비소 성장은 **두 루프가 만나는 곳(공통 진행 바)**, 각 루프의 자기 목표(정비 = 손님 웃게 하기, 복원 = 되살려 팔기, 시대 차 = 발견해 남기기 — 팔아도 전시 기록·이야기가 남음, retention_social)는 지우지 않음. HUD엔 돈 + 정비소 레벨 두 개만은 그대로.
  - 근거: 정비소가 이미 레벨·업그레이드로 맵에서 바뀜(`Upgrades` UpgradeState, 관찰). carbook detroit.md J안 "주유소 건물 스타일로 정비소 시대 업그레이드(창고형 → 집 모양 → 흰 법랑 상자)"가 이 목표의 겉모습이 될 수 있음.

## 9가지 법칙 → 우리 게임

### 1. 기대와 배신 — "이게 왜 안 돼?"
- 위험한 곳:
  - **Gearport 상가 16채·경쟁 정비소·주유소 문**(관찰: 장식) → 들어갈 수 있을 것처럼 보임. → 문에 'CLOSED' 팻말·블라인드 내림·진열창만, 또는 나중에 한두 곳만 열기(다이너 등). 들어갈 수 없는 문은 손잡이·문 앞 매트 같은 '들어오세요' 신호를 빼기.
  - **길가에 세워 둔 차·폐차장 더미**(번들 배경 차 예정) → "이 차도 고칠 수 있나?" → 손님 차와 겉모습이 분명히 달라야(배경 차는 프롬프트 없음 + 색 차분, 손님 차는 번호판·접수 표시·초록 테두리 등 '일감' 표시 하나로 통일).
  - **엔진룸 장식 부품**(관찰: 장식 덩어리 9개 + 진짜 부품) → 진짜 빼는 부품과 장식이 똑같이 생기면 "왜 이건 안 빠져?" → **빼는 부품만** 스캐너 색·프롬프트가 뜨는 규칙을 모든 차에서 같게(장식은 절대 반짝이지 않기).
  - 공구 벽·선반의 공구(추정: 장식) → 들 수 있을 것처럼 보이면 곤란 → 공구 상자(ToolChest)만 상호작용, 벽 공구는 그림자 속·높은 곳.
  - 강 건너 스카이라인 → 보이는 난간으로 막음(관찰: 계획 §4, 보이지 않는 벽 X) ✓.
  - (GPT 추가) **스캐너 빨강 = 고장 원인**이라고 첫 차가 가르친 뒤, Lv3부터 함정(부품은 모두 초록인데 고장 — 예: 단자 부식, alpha_scope)이 그 규칙을 뒤집음 → 첫 예외 때 "스캐너는 **부품 상태**를 보여 줄 뿐, 연결·단자는 따로"를 **플레이로** 납득(예: 첫 함정 차에서 스캐너가 초록 + 단자에 하얀 가루가 반짝, 손님 말 "Battery reads fine — check the terminals." carbook 근거).
  - (GPT 추가) **고쳤는데 결과가 안 보임** → 정산보다 먼저 **증상이 사라지는 순간**(시동이 걸림·끽 소리가 멈춤)을 보여 주기. 튜토리얼 대본의 전후 소리 자동 비교는 아직 코드와 다름(tutorial_script 스스로 적음) → 사람 시험 전에 맞추기.
  - (GPT 추가) **복원은 끝난 것 같은데 팔 수 없음** → flip_loop의 서류(타이틀)·검사·판매 제한이 '겉이 새 차가 된 순간'과 부딪힘 → **사기 전 감정 때** 팔 수 있는지·필요한 검사를 보여 주기.
- 할 일: '겉모습 = 기능' 점검표를 QA 걷기에 추가(wr-builder·wr-dev).

### 2. 일관성 — 하나의 느낌에 모든 시스템을 맞춘다
- 이미 맞는 것(관찰): 손님은 화나도 차를 두고 떠나지 않음, 시간으로 별점 안 깎음(팁만), "Finish later", 잘못 산 부품 전액 환불, 정비소 주인이 나가도 일은 안 사라짐(임시 베이) → '틀려도 괜찮아'와 맞음.
- 부딪힐 수 있는 것: **In a Hurry 손님·Pit Stop Rush(제한 시간)** → 압박은 **표시된 이벤트 안에서만**(H&H의 PvP 지역처럼): 시계 아이콘 손님은 '받을지 고름', Pit Stop은 정해진 코너에서만. 평소 정비소는 언제나 느긋.
- 음악: 사용자가 받은 Cozy Tunes(잔잔한 음악)가 이 느낌과 맞음 — 곡은 사용자가 귀로 고름.
- 검사 질문: "이게 따뜻하고, 손맛 있고, 틀려도 괜찮은가?"

### 3. 좋은 속임수 — 재미를 위해 몰래 돕기
- 제안(0원~S):
  - **진단 불운 막기**: 같은 차에서 두 번 틀리면 차가 더 분명한 단서를 줌(덜컹 소리가 커짐, 웅덩이가 더 진해짐) — 정답을 알려 주진 않음.
  - **고장 뽑기 연속 막기**: 같은 고장이 3번 연속 안 나오게(`FaultService.roll`이 지금 균등 추첨 — 관찰, alpha_scope).
  - **첫 경험 보장**: 첫 손님 2명 고정(튜토리얼, 관찰), 첫 폐차 감정은 '살 만한 차'가 반드시 하나, 첫 복원은 Bronze 이상 나오기 쉽게.
  - 협동 유도: 두 손 부품은 둘이 들면 보통 걸음(관찰: fun_boost #5) ✓.
- 하지 않을 것: 확률 파는 상품·아깝게 실패한 연출·시간 한정 판매 압박(monetization v1과 같음 ✓).

### 4. 조작감 — 현실성이 아니라 '예측 가능성'
- 볼트 풀기·조이기 누르는 시간이 **같은 공구면 언제나 같게**, 렌치 애니메이션 한 바퀴 = 볼트 한 바퀴, 임팩트는 '확실히 빠르게'. 리프트 높이 단계가 언제나 같은 자리에 멈춤.
- 부품 들기·놓기: 놓은 자리에 그대로(굴러가는 바퀴 코미디는 일부러 정한 순간만 — fun_boost #2).
- 할 일: wr-dev — 공구별 볼트 시간 표를 한 곳(Config)에, 폰에서 같은 반응 속도 측정.

### 5. 실행의 틈 — 게임은 '속기사'가 아니라 '통역사'
- **다음에 풀 볼트 우선**: 프롬프트가 여러 개 겹치면 순서상 다음 볼트·지금 일감 부품을 먼저.
- **부품 자석**: 새 부품을 자리 가까이 놓으면 딱 맞게 붙음(정확히 안 맞춰도).
- **바퀴 끼우기 자동 정렬**: 허브 가까이 가져가면 스터드 구멍이 맞춰짐.
- **스캐너는 보는 쪽 가장 가까운 부품**을 자동으로.
- 폰: 버튼·프롬프트 터치 범위를 보이는 것보다 넓게.

### 6. 부드러운 통제 — 자유롭다고 느끼게, 길은 디자인이
- 이미 하는 것(관찰): 튜토리얼 화살표·빛남, 공구 칸이 튀어 오름(Hotbar.nudge), 손님 말이 단서, 건널목이 정비소 문 앞(Gearport) ✓.
- 할 일: 첫 10분 사람 시험에서 "어디로 가지?" 하고 멈추는 곳 찾기(아래 B-2).

### 7. UI — 글자는 가장 느린 정보
- **색 규칙 하나로**: 부품 상태 초록·노랑·빨강이 스캐너·부품 카운터·작업 카드·차 위 표시에서 똑같이. 돈 = 초록, 일감 = 노랑.
- **아이콘 = 3D 모습**: 부품 아이콘(Codex)과 3D 부품이 같은 모양·색이어야(배터리 빨간 + 단자 등).
- **쓰는 자리에 정보**: 부품 카운터에서 "Rosa의 차에 맞음 ✓", 업그레이드 상점에서 "볼트 2.0초 → 0.8초"(몸으로 느끼는 숫자).
- **생김새 = 역할**: 바쁜 손님 = 시계 + 발 동동, VIP = 금색 번호판, 단골 = 이름표.
- 무료 아이콘 팩은 작은 보조 버튼만(관찰: 오늘 결정) ✓.

### 8. 디테일 — 세상이 살아 있다고
- 이미 있는 것(관찰): 엔진룸 진짜 구성, 오일·타이어 자국, 대기실 잡지·화분, SkyLoop 움직임(예정), 가로등 배너.
- 더할 것(작은 것부터): 헌 부품 뺄 때 먼지·녹 가루, 고친 차 시동 소리 바뀜(fun_boost #4 전후 비교 ✓), 손님이 고친 차 보고 웃음·춤(#10), 대기실 손님이 플레이어 쪽 고개 돌리기, 타이어 더미·공구 카트 부딪히면 흔들림, 길 건너 경쟁 정비소에도 가끔 손님 차.

### 9. 전환 비용 — 할 일이 많아도 목표는 하나
- 우리 숫자(관찰): 돈, 정비소 레벨·평판, 별점, 복원 등급, 시대 차 도감, Daily Toolbox, (나중) Crew·Pit Stop 기록 → 많음.
- 할 일: 화면엔 **돈 + 정비소 레벨** 두 개만(HUD 지금 그대로 ✓). 나머지는 그 창 안에서만. 모든 보상 연출이 '정비소 레벨 바'로 빨려 들어가게.

## A. 노가다를 지루하지 않게 (4가지)
1. **반복의 보상이 반복을 빠르게**: 공구·리프트 업그레이드(관찰: ImpactWrench·HydraulicLift·RatchetWrench) ✓ → 상점에 "얼마나 빨라지는지" 숫자.
2. **꼭 해야 하는 반복 = 노가다**: 레벨 문(폐차장 Lv8 등)까지 가는 길을 손님 수리·복원 판매 **둘 다**로(관찰: econ_sim에서 복원할수록 레벨이 느려졌던 문제 → FlipRep 올림 제안) ✓ 방향.
3. **잘게 쪼개고 조각마다 보상**: 볼트 하나·부품 하나마다 소리·반짝, 일 하나 3~6분.
4. **단위 결산(없음)** → 제안: **'오늘의 영수증'** — 접속 끝/다음 접속 때 정비소 영수증 한 장(고친 차 7대, 번 돈 $1,240, 평판 +3, 새로 연 것). 정비소 테마(인쇄된 영수증)라 우리 느낌과 맞음. → 사용자 결정 2.

## B. 로블록스에서 뜨는 게임 (6가지)
1. **차별화**: Fix It Up!(폐차 수리) 대비 우리 = **진단 추리 + 진짜 같은 부품 구성 + 캐주얼 + 같이 하기**. → 첫 5분에 이 차이가 보여야(튜토리얼 Rosa "click-click-click" → 스캐너 → 배터리 = 추리 맛보기 ✓).
2. **작게 만들어 먼저 재미 확인** → **아직 사람이 직접 해 본 시험이 없음**(관찰: 봇·Play 확인만). 프로토 핵심 루프(손님 1명 진단·수리·출고)가 되면 사용자·친구 10분 시험 → 멈춘 곳·웃은 곳 기록.
3. 무엇을 할지 분명 / 계속할 이유 / 성취감 — 일감 카드·레벨 바·출고 환호 ✓.
4. **한 줄기 큰 재미 먼저**: 지금 설계된 서브 시스템이 많음(복원 판매·시대 차·Gearport 놀이 연결·Pit Stop·VIP Rush·Daily·Crew). → v0.2(GPT 반박 받아들임 — 전면 멈춤은 지나침): **사람 시험을 가능하게 하는 코드는 계속**(첫 두 손님 고정, 수리 전후 반응, 막힘 안내, 2인 정산), **새 보상·이벤트 루프(Pit Stop·VIP Rush·Crew·Gearport 놀이 연결 코드)는 첫 1인·2인 시험 뒤로**. 시험에서 alpha_scope 첫 15분 지표 + "재밌던/답답했던 순간"을 보고 다음 코드 순서를 정함. 설계·그림·3D·맵은 계속. → 사용자 결정 3.
5. 추천 알고리즘 = 며칠 유지율·친구와 함께 → retention_social(Daily Toolbox·친구 추천) 방향 ✓.
6. 분석 → 하나씩 고치기: 게시 뒤 Roblox 분석(D1/D7·이탈 지점)을 메인이 주 1회 표로.

## 사용자가 정할 것 → **10-21 사용자 결정: 1·2·3 모두 추천대로**
1. 하나의 느낌 + 공통 진행 목표 '정비소가 자란다'(두 루프가 만나는 곳, 위) — 추천: 그대로.
