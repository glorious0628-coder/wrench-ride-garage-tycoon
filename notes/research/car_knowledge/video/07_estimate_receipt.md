## 1. 손님이 오면 — 수리 주문서(Repair Order, RO) 순서 (B)
1. **손님 정보**: 이름·주소·전화(+이메일) — 추가 수리 연락·"차 다 됐어요" 연락용. &t=0s
2. **차 정보**: 연식·제조사·모델·**VIN**·번호판·**주행거리**(+엔진·변속기·색). &t=33s
3. **증상 듣기**: 손님 말을 최대한 자세히(문진표 쓰는 가게도 있음) — 정비사의 진단을 돕기 위해. &t=95s
4. **요청 작업 적기** — 자주 하는 일(오일·브레이크)은 작업 코드로 줄이 자동으로 채워짐.
5. **공임 시간 붙이기**: '플랫 레이트 책(지금은 프로그램)'의 표준 시간, **0.1시간 = 6분 단위**. &t=126s
6. **부품**: 값 + 새것/중고/재생품 + 부품 번호. 부품 + 공임 = 견적 합계. &t=159s
7. **차 한 바퀴 둘러보기(walk-around)**: 이미 있던 찌그러짐·없는 휠캡·실내 손상을 적어 둠 → 나중에 "가게가 그랬다" 다툼 방지. &t=221s
8. **손님 서명 = 작업 허락**. 서명 전엔 일 시작 X. **추가 작업도 그 사람이 다시 허락**해야 함. &t=221s
- 미국은 **서면 견적이 의무**(없으면 손님이 낼 책임 없음 — 영상 B는 캘리포니아 'ARD' 용어, 주마다 다름).

## 2. 값은 어떻게 정해지나 (A·C)
- **공임 = 책에 적힌 시간 × 가게 시간당 요금**. 시간당 약 $75~140(A, 영상 연도 불명 — 지금은 더 높을 수 있음 "확인 못 함"). &t=30s
- 정비사가 더 오래 걸려도(녹슨 클램프가 부러져 1.5시간) **책 시간(1시간)만 받음**. 예: 닛산 엔진 교체 책 15.7시간 × $80 = $1,256, 실제론 19~20시간 걸림. &t=61s &t=93s
- 반대로 빨리 끝내면 책 시간 그대로 받음 → 정비사 월급도 이 시간으로 계산('플랫 레이트 기사'). 빠른 기사는 하루 일한 시간보다 더 많은 시간을 벌음(B &t=159s). ← **우리 게임 '빨리 하면 이득'과 딱 맞음**.
- **부품은 정가(list price)로 받음**: 가게가 $35.70에 사는 필터를 $57에. 대신 90~120일 안에 부품이 고장 나면 **부품·공임 다시 안 받고 고쳐 줌**(보험 같은 것). &t=156s
- 같이 하면 겹치는 일(밸브 커버 개스킷 + 점화 플러그) → 좋은 가게는 **겹치는 공임은 깎아 줌**. &t=282s
- 정비사가 장비에 $4만~수십만 들임 → "일꾼은 삯을 받을 만하다". &t=249s

## 3. 영수증(인보이스)에 실제로 찍히는 줄 (C — 가게 주인 설명)
| 줄 | 뜻 | 값 느낌 |
|---|---|---|
| **Labor** 공임 | 책 시간 × 시간당 요금 | 제일 큼 |
| **Parts** 부품 | 부품마다 한 줄: 이름 · 부품 번호 · ×개수 · 개당 값 (예: Front disc rotor ×2 @ $50 = $100, Front brake pads ×1 @ $50) &t=245s | |
| **Shop supplies** 소모품 | 브레이크 클리너 반 통·그리스·사포처럼 '조금 쓴 것'을 한 줄로. 프로그램이 부품·공임의 %로 자동 계산, 브레이크 일에 약 $22 &t=327s | 작음 |
| **Hazmat / Environmental** 폐기물 | 헌 오일·필터·고물 처리비 | "차 한 대에 몇 달러" &t=533s |
| **Sublet** 외주 | 가게에서 못 하는 일(정렬기·유리)을 다른 가게에 맡긴 값, 설명 한 줄 ("Sublet: alignment") &t=603s | 가끔 |
| **Tax** 세금 | 지역마다 다름. 그 가게는 **부품·소모품·외주에만**, 공임·폐기물엔 X &t=664s | |
- **"전부 포함" 견적이 좋은 가게**: "부품 100 + 공임 100"이라고만 하면 손님은 200을 생각했다가 세금·소모품까지 290을 보고 화냄 → 그 가게 주인은 **처음부터 다 넣은 한 숫자**를 말함. &t=787s
- **작업 중 새로 찾은 문제** → 차를 올리고 뜯은 뒤 **전화**: "계획대로 가는데, 이게 문제예요 / 볼트가 부러졌어요 → 20분 공임 더" → 손님이 허락하면 진행. &t=910s
- 손님과 다투는 시간 = 돈 못 버는 시간 → **처음부터 솔직하게**. &t=970s

## 4. '보여 주기' — 디지털 점검 (D)
- 정비사가 **태블릿으로 새는 곳·부러진 부품 사진**을 찍어 손님에게 보냄 → "거짓말 아니라는 걸 손님이 사진으로 봄". &t=0s
- (검색 요약, 영상은 안 봄) 이런 점검표는 보통 **초록(괜찮음)·노랑(곧)·빨강(지금)** 3색으로 나눔 — 확인 못 함 수준이니 쓰려면 다음에 근거 보충.

## 우리 게임에 쓰는 법 (판단은 wr-design·wr-ui)
1. **정산 카드 줄 이름** — 지금 `pay.parts`·`pay.labor`·`pay.tip`·`pay.spotOn`·`pay.first`·`pay.star`. 진짜 인보이스 순서는 **Labor → Parts → (Shop supplies) → Tax**. 우리 카드도 **공임을 맨 위, 부품 다음**으로 두면 '진짜 영수증' 느낌(지금 JobService 순서는 부품이 먼저). 팁·보너스는 진짜 인보이스엔 없는 게임 줄 → 아래에 줄 하나 긋고 "Bonus" 묶음으로 따로 두면 자연스러움.
2. **부품 줄 모양**: `Front brake pads ×1 … $50`처럼 **이름 ×개수** — 한 줄에 부품 하나. 부품 번호는 캐주얼 게임엔 빼도 됨(짧은 가짜 번호를 작게 넣으면 '진짜 종이' 맛).
3. **소모품·폐기물 줄은 넣지 않는 게 나음**: 플레이어가 '깎이는 돈'으로 느낌. 넣는다면 **+가 아닌 장식**(예: "Shop supplies — on the house" 0원)으로만. 세금 줄도 X(어린 플레이어에게 의미 없음).
4. **Spot On!(딱 맞춘 진단) = 진짜 '플랫 레이트'와 같은 원리**: 책 시간을 받으니 빨리·정확히 하면 남는 것 → 게임의 빠름·정확 보너스에 근거가 있음.
5. **`n.fixToo` "Want me to fix that too?" = 진짜 '추가 작업 허락 전화'**. 손님이 "Yes, go ahead" 해야 진행 → 지금 흐름과 맞음. 추가 고장을 찾았을 때 **사진 카드(점검 사진)**를 손님에게 보여 주는 연출 = 디지털 점검과 같음.
6. **차 한 바퀴 둘러보기(walk-around)** = 일 받기 전 '원래 있던 흠' 확인 — 나중 이벤트 후보: "손님이 '긁힌 거 여기서 그랬죠?' → 접수 때 사진 보여 주면 평판 지킴"(사람 시험 뒤에).
7. **'오늘의 영수증'**(하루 정리)은 진짜 가게의 '하루 마감 정산(end of day)'과 같은 종류 — 지금 칸(고친 차·번 돈·평판·딱 맞춘 진단)은 그대로 좋음. 근거로 덧붙일 만한 것: **'Hours flagged'(오늘 번 책 시간)** 한 줄 — 진짜 정비사가 하루 끝에 자랑하는 숫자(B &t=159s). 넣을지는 wr-ui·wr-design 판단.
8. 영수증 맨 위 머리말(지금 `WRENCH & RIDE — GEARPORT`)에 진짜 RO처럼 **차 정보 한 줄(연식·차종·주행거리)**을 일별 카드에 넣으면 고증 맛 — 마일리지는 roster 차마다 그럴듯한 숫자.
